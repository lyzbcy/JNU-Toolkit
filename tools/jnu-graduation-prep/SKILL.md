# 江南大学毕设材料准备与审查

## 首次使用与输入

每日首次调用时，将本目录 `scripts/check_update.py --background` 以 Python 3 运行一次。它在后台检查本仓库公开版本，失败不影响本次任务；不创建定时任务、不上传材料。更新仅涉及此 Skill 的公开文档，脚本自身变更需随正式安装包更新。

1. 读取本人当年学校通知、学院通知、导师会议或反馈、学校写作规范、正式样例和本人系统已核验的课题信息。若缺实际课题，先使用 [jnu-graduation-check](https://github.com/lyzbcy/JNU-Toolkit/tree/main/tools/jnu-graduation-check) 或本人提供的真实证据核验。
2. 以本人正式题目、性质、来源、导师、当年学生提交和审核窗口为准；区分导师建议与系统硬截止，不照搬历史年份和样例学生身份。
3. 建立材料索引与状态：尚未开始、准备稿、已审阅、已提交、已审核；准备稿不等于已提交。档案留在本人工作区。

## 材料提前准备

- 任务书：学生手册明确学生查看导师下达的任务书。可提前整理研究目标、任务、技术路线、计划、成果及风险控制供老师参考；不代填导师意见、签名、审批或声称已经下达。
- 开题报告：优先复制当年导师提供的样例，仅修改学生填写字段与研究内容。保留版式、表结构、封面和意见栏；题名与系统逐字一致。准备科学依据、研究内容、方法/技术路线/实验/可行性、计划、成果、特色和待解决问题。将参考文献与正文关联。
- 外文：寻找真实、相关、可核验出处的英文文献，优先开放许可。按导师实际字符数要求统计正文，说明是否含空格；不借元数据或参考文献填充字数。原文与译文逐段对应、注明出处及许可；若节选须注明范围并附完整原文，是否允许节译由导师确认。
- 论文：以学校给的 Word 母版建立工作稿。按当年要求核对设计总说明/摘要、英文对应、关键词、目录、页眉页脚、页码、章起始页、图表编号、公式及引文。清除所有样例身份、旧课题、示例图表和无关正文；不把未开展的实验、数据和结论写成事实。
- 研究证据：将需求、设计、实现、测试、版本、证据编号关联起来。记录真实实验与用户反馈，区分原始数据、推算、意向、计划和实际结果；旧版本证据明确标注，不能替代最终运行验收。文献综述和答辩工作稿可先准备，最终版随研究结果更新。
- 运行说明：写明必要环境、确切版本、操作步骤与预期，最终归档时依据冻结版本验证。其他材料按实际通知与本人真实经历准备。

## 审查与下一步

1. 以样例为模板而非素材库；旧 .doc/.ppt 转成现代格式时保留原件，检查转换后分页、表格、字体和字段。
2. 用 Word 或可靠渲染工具回读每页，核对封面、表格分页、目录、图题表题、孤行和签名栏；检查系统题名、段落、引用以及英文字符统计。记录验证证据及不足，不宣称未核验结果已完成。
3. 结合工作稿形成下一步清单，标记必须等导师正式任务书、审核、研究实测或系统开放的事项。学生操作手册说明任务书下达后方可提交开题，开题完成后方可提交文献综述；以实际系统和当年通知复核。
4. 本 Skill 只负责准备和审查。正式提交须按本人指令及平台真实流程，提交后回读状态；尚未实测的提交动作不能说已实现。公开沉淀仅留通用步骤，不包含个人身份、选题正文、学校账号、截图、内部项目或原始研究数据。
