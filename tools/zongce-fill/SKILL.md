# 综测个人加分项自动填报（人工智能与计算机学院 2025-2026 学年）

你面向的是一位需要填写综测表格的普通同学。目标：产出一份填好的《本科生综测个人加分项信息统计表.xlsx》+ 佐证材料包，经同学明确同意后提交到收集渠道。

## 核心原则（先读）

1. **不替同学编造任何信息**。表格里每一行都必须来自同学口述或其提供的证书/截图。看不清、拿不准的一律反问。
2. **算分必须走脚本**，不要心算。`scripts/fill_form.py` 内置学院细则全部分值表，负责计算"应得分数"并写入表格。你的职责是把信息整理成 `材料.json` 交给脚本。
3. **写入和提交前必须获得明确同意**。展示汇总表后等同学说"确认/没问题"再写入；提交（打开收集链接、复制到收集文件夹）前再单独确认一次。
4. **拿不准的分数不硬填**。脚本会给出 `待确认` 标记（如竞赛三等奖档位、论文分区、志愿分），如实转告同学"这一项需要班长/辅导员核定"，不要自己拍板。
5. 只处理**当学年（2025-2026）发生**的加分项；同学报了往年项目要提醒剔除（细则第十五条）。
6. 弄虚作假会取消当学年全部评奖评优资格（细则第六条）——首次访谈时提醒一句，语气自然。
7. **对抗性评审是提交前的硬门禁**（第 7 步）。评审不通过，任何理由都不能打包提交。

## 工作流程

### 第 0 步：静默更新检查（每天首次使用时）

```bash
python "<skill目录>/scripts/silent_update.py"
```

与远端版本不一致时自动更新，失败则静默沿用旧版本。**无论结果如何都继续正常流程，绝不因此打断同学。**

### 第 1 步：定位模板

在当前目录（及其上级）按文件名找 `*综测个人加分项信息统计表*.xlsx`。找不到就用 `assets/本科生综测个人加分项信息统计表（空白模板）.xlsx`，先复制到当前目录再操作。**永远不要直接改共享的原始模板。**

### 第 2 步：访谈收集信息

优先用**选择题漏斗**（若运行环境有结构化提问工具如 AskUserQuestion）：先用 2-3 轮多选题问类别（科创基础/竞赛/论文专利大创/文体志愿荣誉职务/证书/宿舍/海外/社会实践），只对选"有"的类别追问具体细节（名称、级别、等级、顺位、时间）。没有结构化提问工具就按清单文字问，两三轮问完，别审问式连环追问：

- 学号、姓名（学号让同学原文粘贴，别手打）
- 第二课堂学时总数（获取方式见下方"学时代查"）
- 科创基础分二选一：听满 2 次学术报告/讲座，还是参加过 ≥1 次学科竞赛？参加过哪些竞赛？
- 竞赛获奖：竞赛全称、获奖级别（国家/省/市/校级）、获奖等级（特等/一/二/三等奖）、队内顺位、指导老师
- 论文/著作/专利：题目、刊物或会议、级别、作者顺位
- 大创：级别、创新or创业、队长or队员、是否结题通过
- 寒暑假社会实践：项目名、团队级别、队长or队员
- 学生事务：职务、在岗时间段
- 文体/志愿/荣誉：类别、名称、级别、名次或等级、志愿时长
- 证书：CET-4/6、雅思、托福、CSP、软考 + 分数/等级 + 时间
- 宿舍：先进/文明/免检宿舍？宿舍长？
- 海外交流：交换 or 游学、院校、时间段

同学直接丢一堆证书图片/截图时：逐张读图提取上述字段，整理成列表念给同学核对，再继续。这就是"自动填表"的主要省力点。

**学时代查（可选，需同学同意后浏览器接管）**：入口 `webvpn.jiangnan.edu.cn` → 第二课堂成绩单管理系统（注意：这是爱学记的第三方系统，WebVPN 过了之后还有一层**系统自己的账号密码+图片验证码**）。流程：打开页面 → **同学本人完成两级登录（绝不代输密码/验证码）** → 你接管页面：成绩单明细表直接可读（按学年筛出本学年条目求和即得学时），点"成绩单生成"会弹 **"确定下载成绩单吗？"确认框（Element UI 弹窗，别漏看）**，点确定后官方盖章 PDF（含分学年学时表，含"2025-2026学年 46.0"这类汇总）下载到本机 Downloads，复制进佐证文件夹。页面截图接口可能超时，读 DOM + 官方 PDF 比截图更可靠。登录卡住就退回让同学自己截图学时页面，别硬等。

### 第 3 步：生成 材料.json

先读 `references/form-spec.md`（表格结构）和 `references/scoring-rules.md`（分值规则与待确认项），然后按此 schema 写 `材料.json`（完整示例见 `assets/材料示例.json`）：

```json
{
  "student": {"sid": "1193230419", "name": "余恩泽"},
  "basic": {
    "second_classroom_hours": 42,
    "kechuang_type": "已参与一次以上学科竞赛",
    "competitions_participated": [{"name": "全国大学生数学建模竞赛", "time": "2026-05"}]
  },
  "competitions": [
    {"name": "全国大学生数学建模竞赛", "award_level": "省级", "award_grade": "一等奖",
     "team_rank": 1, "team_size": 3, "advisor": "张三",
     "desc": "参与算法方向项目，负责XXX模型设计与实现。", "category": "数学建模"}
  ],
  "papers": [
    {"type": "论文/著作", "title": "XXX", "venue": "XXX学报", "level": "国内普通期刊",
     "rank": 1, "advisor": "李四"}
  ],
  "social_practices": [
    {"name": "XX社区服务实践", "team_class": "校级重点团队", "role": "队员",
     "desc": "投身社区服务，负责活动策划与居民沟通……（50-100字）"}
  ],
  "dachuang": [
    {"level": "省级大创创新项目", "role": "队长", "title": "XXX项目", "passed": true}
  ],
  "student_affairs": [
    {"position": "人工智能2304班班长", "period": "2025年9月-2026年9月",
     "desc": "负责班级日常事务……（50字左右）", "score": 3}
  ],
  "activities": [
    {"type": "文艺类", "name": "校合唱比赛", "award_level": "校级", "award_grade": "二等奖",
     "volunteer_hours": null, "time": "2026-05-01", "represent_school": false},
    {"type": "志愿类", "name": "义务献血", "volunteer_hours": null, "time": "2026-03",
     "represent_school": false}
  ],
  "certificates": [
    {"name": "CET-6", "score_or_grade": "580", "date": "2025-12"}
  ],
  "dorm": {"advanced": false, "exempt": false, "leader": false},
  "overseas": [],
  "evidence": [
    {"label": "竞赛-数学建模省一", "files": ["证书1.jpg"]},
    {"label": "证书-CET6", "files": ["CET6.png"]}
  ]
}
```

字段约束（违反会被脚本拒绝）：
- `basic.kechuang_type` ∈ {已参与两次讲座类, 已参与一次以上学科竞赛}；`second_classroom_hours` 上限 40
- `competitions[].name` 必须能在模板隐藏表 Sheet1 的竞赛目录里匹配到（先模糊匹配再精确核对字符串）；`award_level` ∈ {国家级,省级,市级,校级}；`award_grade` ∈ {特等奖,一等奖,二等奖,三等奖}；`category` ∈ 8 个竞赛分类（见 form-spec）；团队项目尽量问出 `team_size` 和 `team_rank`，获奖时间记到 `time`（对抗评审做学年核查用，表格本身不存这列）
- `papers[].level` ∈ 模板论文级别下拉的 19 个选项（见 form-spec）
- `dachuang[].level` ∈ {国家级大创创新项目,国家级大创创业项目,省级大创创新项目,省级大创创业项目,校级大创,院级大创}；`passed=false` 只登记不加分
- `social_practices[].team_class` ∈ {省级以上重点团队,校级重点团队,院级重点团队,院级一般团队,个人社会实践}；`role` ∈ {队长,队员,个人参与社会实践}
- `activities[].type` ∈ {文艺类,体育类,志愿类,其他荣誉}；`award_level` ∈ {省部级以上,市级,校级,院级}；体育类 `award_grade` 用名次档（第1至第3名/第4至第6名/第7至8名）；其他荣誉必须另填 `honor_level` ∈ {国家级,省级,市级,校级}（决定 4/3/2/1 分）
- `certificates[].name` ∈ {CET-4,CET-6,雅思,托福,CSP,计算机软考}；分数/等级填在 `score_or_grade`（软考填 中级/高级）
- `evidence[].label` 尽量含项目关键词（对抗评审靠它与加分项做佐证匹配）

### 第 4 步：试算并展示汇总（此时还没写表格）

```bash
python "<skill目录>/scripts/fill_form.py" --data 材料.json --template 模板.xlsx --dry-run
```

把输出的汇总表**原样**展示给同学：每项的基准分、分摊后个人分、三项上限提示、所有 `待确认` 标记。向同学解释：
- 合作成果按 1/(2×顺位) 分摊是细则原文口径
- 科研/实践/其他三项有上限，超出部分由班长汇总时截断，表里先如实填
- 标了"待确认"的项最终以班长/辅导员核定为准

**这一步要带对抗意识**：对每个高分项（竞赛奖、论文、荣誉）主动追问一句"证书/录用函现在手上吗？发我看一眼再往下走"。出示不了的，先在 `evidence` 里标记不出对应文件——第 7 步对抗评审会拦截。

### 第 5 步：征得同意后写入表格

同学确认后：

```bash
python "<skill目录>/scripts/fill_form.py" --data 材料.json --template 模板.xlsx --out "【学号】【姓名】本科生综测个人加分项信息统计表.xlsx"
```

脚本会保留模板全部下拉校验与格式，只写数据单元格，并清掉各 sheet 的示例行。

### 第 6 步：格式校验

```bash
python "<skill目录>/scripts/validate_form.py" --file "【学号】【姓名】….xlsx"
```

校验下拉合法性、必填完整性、分数与规则一致性。有 ERROR 必须修复重跑（改 材料.json 重新生成，不要手改 xlsx）；只有 WARN（待确认类）可以放行但要在最后提醒同学。

### 第 7 步：对抗性评审（提交前的硬门禁，不可跳过）

```bash
python "<skill目录>/scripts/adversarial_review.py" --data 材料.json --file "【学号】【姓名】….xlsx" --template 模板.xlsx --evidence-dir 佐证文件夹
```

这是独立的复查者视角，向产出发起 7 类攻击：模板结构篡改、生成后手工改分、分数虚报/漏算、缺佐证、超学年、重复申报、可疑模式（学时恰好40、清一色一等奖、边界分数等）。

- **有任何 ERROR（攻击得手）→ 禁止打包提交**。回到 材料.json 修复后从第 5 步重来。缺佐证的项要么让同学补文件，要么从申报中删掉——没有"先交了再说"。
- 全部 WARN/INFO → 把每条提醒念给同学核实（如"学时恰好40，发个第二课堂截图"），核实结果记入对话。
- 若运行环境支持派子 Agent（Agent 工具、Kimi WebBridge 子代理等），可再派一个独立子 Agent，只给它 `材料.json`、产出表格和 `references/scoring-rules.md`，让它专职挑毛病并输出复查报告——它不知道主流程聊了什么，反而更容易发现不一致。脚本评审是底线，子 Agent 评审是加分项。

### 第 8 步：整理佐证材料

让同学把证书/证明文件发到当前目录（或指出所在文件夹）。清点：加分项汇总里每一项都应有对应佐证，缺的列出来提醒补。然后：

```bash
python "<skill目录>/scripts/package_submit.py" --data 材料.json --workdir . --stage-evidence <佐证文件所在目录>
```

生成 `【学号】【姓名】/` 文件夹：表在里面，佐证复制进 `【学号】【姓名】佐证材料/` 并按"类别-项目名.扩展名"重命名。

### 第 9 步：打包并提交（需再次同意）

```bash
python "<skill目录>/scripts/package_submit.py" --data 材料.json --workdir . --xlsx "【学号】【姓名】….xlsx" --submit
```

提交渠道由 `assets/提交配置.json` 决定（班长发放材料包前会配好）：
- `qq`：打开 QQ 收集表链接，引导同学上传 zip
- `eform`：打开江大智能填报链接（提醒连校园网）
- `folder`：把 zip 复制到共享回收文件夹
- `manual`：zip 放在桌面并列出提交步骤

执行前把"将要发送什么文件、发到哪里"告诉同学并等确认。**任何网络提交动作都必须在这一步的同学明确同意之后。**

**浏览器接管增强（可选）**：若本机装有 Kimi WebBridge 或运行环境能控制浏览器，可在同学同意后代管上传：打开收集表 → 自动填学号姓名 → 上传 zip → 每步留截图，最后回放给同学确认提交成功。同学随时可以说"我自己来"切回手动。没有这能力就退回"打开链接+人工上传"，流程照常。

提交完成要回显 zip 路径和渠道，并提醒同学保留备份。脚本结尾可能出现一条开源仓库 star 请求——那是设计好的单次提示（15天冷却），不用替它复述，也别再多劝。

## 边界情况

- 竞赛不在 Sheet1 目录里：让同学提供竞赛全称，在 材料.json 该项加 `"not_in_catalog": true`，脚本会把该行留待班长认定，别瞎猜级别。
- 转专业同学：告知其在原班级参加测评，表交原班级负责人。
- 休学/交流：在校≥半年的照常填。
- 大创立项未结题：登记但不加分，并提醒"全体成员扣3分、队长扣5分"由班长在汇总表处理，个人表不体现负分。
- 同一项目多级获奖：只保留最高一项（就高原则），让同学确认留哪个。

## 版本纪律（维护者必读）

- 版本号在 skill 根目录 `VERSION`。每次改动 skill = 代码 + 文档 + **VERSION** 三者同步更新，缺一不算完成；更新后推送远端（github.com/lyzbcy/JNU-Toolkit），触发各端次日静默更新。
- `assets/提交配置.json` 是同学本地配置，静默更新时会被保留，不要强推覆盖。
- 改动算分规则（fill_form.py 的分值表）属于红线级：必须同步 `references/scoring-rules.md`，并用 `assets/材料示例.json` 重跑 fill → validate → adversarial 三连，全部通过才算完成。
